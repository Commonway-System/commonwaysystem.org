## Accessibility standing rule: every change gets an accessibility check of the WHOLE page it touches

**This applies to every page added and every edit made from 2026.09.26 on, however small.** Fixing one illustration, one paragraph, one table cell, or one token still means checking the *entire page* (or, for a component or style change, every page type that uses it), not just the bit that changed. The site owner set this rule explicitly and it is not optional or "only for big changes." A full-site scan is **not** required per change: that is reserved for the site owner's separate Website specification audit (see the Roadmap note in the release-history section). What is required each time:

1. **Run axe on each page you touched or added**, in light AND dark mode, at desktop width AND 375px, using tags `wcag2a, wcag2aa, wcag21aa, wcag22aa, best-practice`. Recipe below. Zero violations is the bar; if one remains, fix it (or, if it is a real judgment call, flag it to the user and record it in `/about/accessibility-policy/`'s Known limitations, never silently ignore it).
2. **Do the "mindset review" that axe cannot do**, on that whole page: reading/heading order makes sense (one `h1`, no skipped levels, a card title that repeats the `h1` is not a heading); every image has meaningful `alt` or `alt=""` if purely decorative; link text makes sense out of context; color is never the only signal (a text label, icon, or pattern accompanies it); interactive things are real `<button>`/`<a>` with visible keyboard focus and a tap target of at least 24x24 CSS px; tables have real header cells; anything that moves has a pause path and respects `prefers-reduced-motion`; collapsed content (`<details>`, accordions) is checked *expanded* too; layout survives 375px width, the largest Display settings text size, high-contrast mode, and simplified view (test new components in all of them, not just a sample page); focus is not hidden behind the sticky navbar/`TocMobile` bar (`scroll-padding-top` on `html` handles this, don't reintroduce per-element `scroll-margin`).
3. **Compute contrast, don't eyeball it** (WCAG formula, see Working conventions). Text needs 4.5:1, UI components and focus indicators 3:1, in both themes and under any overlay (the pointer halo, hero art).
4. **Fix genuine failures directly; flag judgment calls.** New content pages must also be reachable by the skip link, `<main>`, and the text-only build (below) without extra work: don't bypass `PageLayout`.
5. **Keep the paper trail current:** if a fix or a new limitation changes what's true about accessibility, update `/about/accessibility-policy/` (its "Known limitations" section is the single public list; it currently says no open items from the 2026.09.26 audit remain, and lists what has NOT been tested), and mention it in that day's `/about/release-history/` entry.
6. **Say in the final report what was checked and what wasn't** (e.g. "axe clean on X in both themes at both widths; not tested with a real screen reader"). Do not claim conformance.

**axe recipe (how the 2026.09.26 audit was run; no test framework is installed).** Since 2026.10.14 the quicker route is `scripts/qa/qa.mjs` (see Commands), which drives headless Chrome directly. The in-pane recipe still works when that isn't available: the Browser pane can't run Playwright, so pages are loaded into hidden same-origin iframes of a dev-server tab and axe-core is evaluated inside each one:

```js
// in javascript_tool, on any http://localhost:5173/ page
const src = await fetch('https://cdnjs.cloudflare.com/ajax/libs/axe-core/4.10.2/axe.min.js').then(r => r.text())
const f = document.createElement('iframe')
f.style.cssText = 'position:fixed;left:0;top:0;width:1280px;height:900px;border:0;opacity:0;z-index:-1' // width 375 for the phone pass
document.body.appendChild(f)
await new Promise(r => { f.onload = r; f.src = '/patterns/collectors/default/' })
await new Promise(r => setTimeout(r, 1800))                       // let Svelte hydrate
const win = f.contentWindow, d = win.document
d.documentElement.dataset.theme = 'dark'                           // then again with 'light'
await new Promise(r => setTimeout(r, 2500))                       // theme switch animates; scanning sooner gives FALSE contrast failures
win.eval(src)
const r = await win.axe.run(d, { runOnly: { type: 'tag', values: ['wcag2a','wcag2aa','wcag21aa','wcag22aa','best-practice'] } })
r.violations.map(v => v.id + ' x' + v.nodes.length + ' ' + v.nodes[0].target.join(' '))
```

Gotchas that each cost time once: (a) a single `javascript_tool` call times out at ~45s, so start long runs as a background `async` IIFE that pushes into `window.__results` and poll with short waits; (b) the pane is usually `visibilityState: 'hidden'`, so `requestAnimationFrame`, CSS transitions and `:focus` matching don't behave (verify focus/reveal styles by forcing the state, and don't rely on rAF-driven code in tests); (c) `details` cells are collapsed until opened, and axe ignores collapsed content, so set `details.open = true` and rescan (this is how the GuidanceTable `.guidance__note` contrast failure was found); (d) axe reports "incomplete" for text over SVG shapes, tiny numeric badges, and partly-scrolled sticky panels; measure those by hand (computed colors + the contrast formula) and record the result instead of leaving them "needs review"; (e) iframes share `localStorage`, so set `commonway-display-settings` *before* loading them to test a Display settings mode, and remove it afterward; (f) a temporary helper file dropped in `static/` to load a driver script must be deleted before finishing (it would ship); (g) `pnpm run build` stops the dev server, so `preview_start` again before browser checks.

**Audit and fixes.** All 165 pages were scanned with axe-core 4.10.2 (desktop dark, desktop light, 375px light; 495 scans). Everything it found was fixed, and nothing from that audit is open:

- **Unlabeled `<aside>` landmarks:** `Sidebar` ("Sidebar"), `Toc` ("Table of contents"), `MediaFilters` desktop ("Media filters") now have `aria-label`s.
- **Heading order:** `PatternCard` and `RetrofitCard` (both removed 2026.10.20; `PageHeader`'s demo mode does the same) titles are `<p>`, not `<h3>` (the title repeats the page `<h1>`, so a heading only added a duplicate, out-of-order outline entry). `MediaCard` takes a `headingLevel` prop (default 3 for Related Media under its `h2`; `MediaGallery` passes 2 so cards sit directly under `/media/`'s `h1`).

- **Tap targets:** `Citation.svelte` links keep the same visible pill but have a 24px hit area via a transparent 5px border + `background-clip: padding-box` + negative margins (order matters: `background-clip` must come *after* the `background` shorthand or it resets), and `min-width: calc(1.5em + 10px)` because `box-sizing: border-box` otherwise eats into the pill width.
- **Empty table headers:** the Who/How/Why table on `about/commonway-system/` has visually hidden header text (`<span class="cw-sr-only">Question</span>` etc., a raw inline span is safe in markdown).
- **Release History stray `<img>`:** that page's changelog strings are rendered as raw HTML (`{@html}`), so a backticked `<img>` in prose became a real empty image and backticks showed literally. `releaseBodyHtml()` now converts backtick spans to escaped `<code>` via `inlineCode()`; write backticks freely in changelog strings.
- **Axe "incomplete" items** (citation badges 129 pages, sidebar links ~100 pages, speed-limit sign SVG text) were checked by hand: badge 5.01:1, sidebar links 8.5:1 light / 10.6:1 dark, sign black on white. Documented on the policy page.

**Skip link and mobile outline.** `GlobalLayout.svelte` renders `.skip-link` ("Skip to main content") as the first focusable element; its click handler focuses `#main-content` (plain hash navigation wouldn't move focus) and reveals via `:focus` translateY. `html { scroll-padding-top }` (navbar height + 1rem, +4.75rem below 1180px for the bar) replaced the old per-heading `scroll-margin-top` rules so keyboard focus, anchors and headings all clear sticky UI (WCAG 2.4.11). `TocMobile.svelte` is the sub-1180px "On this page" bar (sticky under the navbar with a 0.75rem gap; disclosure button with `aria-expanded`, current-section text, list of headings; closes on Escape, outside pointerdown, or selection; selection focuses the heading). Its scroll logic lives in `src/lib/theme/toc-tracking.ts` (shared with the desktop `Toc.svelte`: store `tocState {visible, current}`, started once from `GlobalLayout`, computed **directly on scroll, not via `requestAnimationFrame`**, because rAF is paused in a hidden tab). "Current" = last heading at or above the viewport top (threshold navbar + bar + 20px so an anchor jump lands as current); "visible" = headings on screen. Desktop rail styling: visible = darker/medium, current = teal, bold, left bar, `aria-current="location"`.

**Hero pause (WCAG 2.2.2).** `Hero.svelte` owns a `paused` state (`localStorage` key `commonway-hero-motion-paused`, every access in try/catch) and a "Pause/Play animation" button; `InkHalftone.svelte` takes a `paused` prop (an `$effect` cancels/restarts the rAF loop, keeping the last frame on the canvas; `lastTime` lets a resize redraw the frozen frame); `.hero-bleed--paused .hero-glow` sets `animation-play-state: paused`. The button is `display: none` under `prefers-reduced-motion: reduce` (nothing animates there).

**Display settings** (`src/lib/theme/display-settings.ts`, `DisplaySettingsPanel.svelte`, `DisplaySettings.svelte`, `PointerHalo.svelte`; CSS at the end of `base.css`, tokens at the end of `tokens.css`). State is a `displaySettings` store persisted in `localStorage` key `commonway-display-settings` (JSON, try/catch) and mirrored as data attributes on `<html>`: `data-text-size` (`default|large|larger|largest`, i.e. `html { font-size: 100/112.5/125/150% }`, relative to the reader's own browser setting), `data-contrast` (`default|high`), `data-view` (`default|simple`), `data-focus` (`default|enhanced`), `data-pointer` (`default|large`), `data-halo` (`off|on`), plus `data-font` (`default|lexend|atkinson|opendyslexic`) and `data-symbols` (`off|on`); the reading ruler has no attribute (`ReadingRuler.svelte` reads the store). See the "Reading font and Color symbols" and "Reading ruler" notes below. **`src/app.html` has an inline script that applies the saved values before first paint; its attribute names and the `prefers-contrast: more` default must stay in sync with `apply()`/`initDisplaySettings()` in `display-settings.ts`.** Entry points: an "Aa" button in `Navbar` (hidden at <=940px) and a `<details class="sidebar__display">` inside the mobile drawer's primary-nav block (the navbar has no room for a sixth item at phone width). The navbar panel is `position: absolute` against the sticky `.navbar` (so `.dsb` must NOT be `position: relative`), `right: 1rem`, and capped with `max-height: calc(100dvh - var(--cw-navbar-height) - 1.5rem)` + `overflow-y: auto` (added after a report that it ran off-screen at the largest text size); the drawer copy scrolls with the sidebar.
- **Text size:** works because the type scale is rem-based. **Media queries do NOT respond to it** (they use the browser's initial font size, not the `html` font-size), so layout breakpoints don't move; the navbar therefore now wraps (see below) instead of overflowing. Any new `px` font size or fixed-height element will fail to scale or overflow at "largest": use rem and test at 150%.
- **High contrast** (`html[data-contrast='high']` token overrides, plus `[data-theme='dark']` variant; underlined content links; solid navbar; solid card borders; `::after` text labels on `.pic__meta`/`.ric__meta` per `data-classification`/`data-scale` so classification is text, not just color). The 9 classification ramps are deliberately left alone. Axe was clean on 9 page types in both themes.
- **Simplified view** (`html[data-view='simple']`): plain system font via `--cw-font-*`, all animation/shadow/transition off, hero art/card images/mark hidden (`.mc__image img` only, the endorsement pill lives in `.mc__image`), single column and no sidebar/toc at >=941px, hero text forced to page colors with `!important` (the hero's own selectors are `(0,3,0)`), and every `<details>` opened by `expandAllDetails()` (called on apply and after navigation from `GlobalLayout`).
- **Enhanced focus** is a 4px `#ffd60a` outline + 2px `#141414` box-shadow gap; **large pointer** is a 40px inline-SVG cursor (fallback `auto`/`pointer`, text fields keep `text`); **pointer halo** is a fixed 3rem circle, 20% yellow fill + 2px ring, `pointer-events: none`, hidden for touch. Since 2026.10.14 it is also a `popover="manual"` kept at the top of the browser's top layer by `keepOnTopLayer()` (`src/lib/theme/top-layer.ts`): the search `<dialog>` and the Display settings popover are top-layer elements that paint above any z-index, so the halo re-shows itself (hide + show) whenever another dialog or popover opens. Any new always-on overlay that must stay above dialogs needs the same treatment; the Reading ruler deliberately doesn't (the boxes stay unshaded). Testing tip: Puppeteer's default screenshot mode (`captureBeyondViewport: true`) drops top-layer overlays, so pass `captureBeyondViewport: false`. The 20% fill is computed: 30% dropped dark-mode teal text to 3.8:1, 20% keeps it at 5.0:1.
- **Navbar wrapping:** `Navbar.svelte` now uses `min-height` (not `height`), `flex-wrap: wrap`, `.navbar__links { flex: 1 1 0 }`, and a `ResizeObserver` publishes the real height to `--cw-navbar-height` on `<html>` (sticky sidebar/toc/anchor offsets all read that token). The "Version" label shortens to "V." below 1100px (was 940px). **Below 420px the version link is hidden entirely** (2026.10.14): the five mobile items need about 368px plus iOS's wider monospace date, so 360-390px phones wrapped the theme toggle to a second row and the drawer's Search button sat partly under the taller header on real phones. Don't add a sixth item to the phone navbar without re-measuring. This also fixed a pre-existing sideways overflow at 941-~1000px. **Open:** at "largest" the header is ~180px tall on wide screens (127px at 375px), eating viewport; making it non-sticky at large sizes was proposed, not built.

**Large pointer fix (2026.09.26, later):** the old rule only covered `body`, links, buttons, `summary`, `label` at low specificity, so form controls (native default cursor) and components with their own scoped `cursor: pointer` (search button, panel controls) showed the small pointer. ## Session practice notes from the Display settings additions (2026.09.26, later)

- **The dev server may already be running from another Claude session.** `preview_start` then fails with "Port 5173 is in use by another chat's dev server"; don't fight it, just `navigate` the Browser pane to `http://localhost:5173/...` and test there.
- **After editing `base.css` or another global stylesheet, check the page actually has the new rule** (e.g. read a new custom property with `getComputedStyle(document.documentElement).getPropertyValue(...)`, or reload with a fresh `?x=N` query). A navigation right after an edit served stale CSS once and made a correct fix look broken.
- **Hidden-tab caveats again:** `element.focus()` did not fire `focusin` in the test tab (dispatch a `FocusEvent('focusin', {bubbles:true})` instead), and a JS `scrollIntoView` followed by a screenshot can come back blank (use `computer` scroll or navigate to an `#anchor`). `zoom` with a region is not supported in the Browser pane; measure geometry with `getBoundingClientRect` instead. A `<Range>` around a text node gives a real text box for alignment checks.
- **You can't see the mouse pointer in screenshots.** Verify cursor rules by reading `getComputedStyle(el).cursor` and render the cursor SVGs on screen to check their shape.
- **Mobile drawer top padding:** `Sidebar.svelte`'s `<940px` rule uses `padding: 2.25rem 1rem 2rem` (was 1rem) so the Search button clears the header; the user saw it partly hidden on a real phone though the 375px emulation showed a 16px gap, so real-phone header heights can differ from the Browser pane (iOS Safari). If it recurs, ask which phone/browser and check `--cw-navbar-height` against the real header.
- **`DisplaySettingsPanel` is mounted twice** (navbar and mobile drawer), so anything with a document-level identity (radio `name`, `id`, `aria-labelledby`) must be made unique per instance with `$props.id()`.
- **Scroll cues for a scrolling panel:** CSS scroll shadows (the table-wrapper trick, vertical) plus a visible thin scrollbar plus a decorative "Scroll for more" pill that disappears at first scroll; keep the pill outside the scroller so it doesn't change `scrollHeight`.
- **Reading fonts and other third-party font/icon assets are self-hosted**, never loaded from a CDN, so the privacy policy's "nothing leaves the browser" stays true. New third-party assets get an entry in `THIRD-PARTY-NOTICES`.
- **A reader-facing setting needs five things:** the store field and `apply()` line in `display-settings.ts`, the matching line in `app.html`'s inline script (if it sets a `<html>` attribute), the panel control, the Accessibility Policy bullet, and an axe pass with it switched on (both themes, 375px, panel open).
