## Architecture (continued)

- `Hero.svelte` and the `Home*` section components — the homepage (`src/routes/+page.md`, rebuilt 2026.10.18; see "Homepage (2026.10.18)" below). `Hero` renders its own `<h1>` rather than relying on `PageLayout`'s usual `fm.title`-driven one; the homepage's frontmatter sets `hideTitle: true` to suppress `PageLayout`'s default `<h1>` (`{#if fm.title && !fm.hideTitle}`, only this page uses it) and `wide: true` (`class:cw-content--wide={fm.wide}`, 88rem instead of the 46rem prose column, also used by `/media/`). **Specificity gotcha:** `base.css`'s `.cw-content h1/h2/p/ul/li` prose rules (one class plus an element) compete with component rules; give every element a class (a class-only scoped selector wins) rather than styling bare elements, and where a `:global(.ancestor)` prefix is needed on a base rule, every `@media` rule for the same property needs the identical prefix too, or the base rule wins at every width (this once broke the old `FeatureGrid`'s mobile columns and `Hero`'s mobile title size).

  **`Hero`'s section is full-bleed and permanently dark**, deliberately not following the site's own light/dark toggle: `GlobalLayout.svelte` computes `isHome = page.url.pathname === '/'` and, only on that route, collapses `.shell`'s 3-column grid (`sidebar content toc`) down to a single `content` column via a `.shell--full` class (declared last in that file's `<style>` block specifically so it wins the specificity tie against the two responsive `.shell` breakpoint rules above it, at every viewport width, not just where it's declared) and hides `Sidebar`'s rendered `<aside>` at `>=940px` via `.shell--full :global(.sidebar) { display: none }`. `Sidebar` itself stays mounted unconditionally even on the homepage: below 940px it's still the only way to reach the navbar's primary links from the mobile hamburger drawer (see the `sidebar__primary-nav` note above), and `position: fixed` there already takes it out of grid flow, so it doesn't need hiding at that width. `Hero.svelte`'s own `.hero-bleed` then escapes `PageLayout`'s `.cw-content` 46rem max-width (and the padded `.page` around it) with the standard `left:50%; margin-left:-50vw; width:100vw` breakout trick, which works through however many centered ancestors sit in between since `100vw` is always the true viewport width; this only avoids introducing a horizontal scrollbar because `base.css` already sets `scrollbar-gutter: stable` on `html`. Because dark-mode's own page background (`--cw-paper` = `#141414`) is identical to `--cw-ink-fixed`, `Hero`'s `--hero-bg` custom property gets a `[data-theme='dark']` override to a deep teal-charcoal (`#0e211d`) so the hero still reads as a visually distinct band in dark mode too, not just light mode where the plain fixed-ink background already contrasts against the light paper. (Its animation has a Pause/Play button since 2026.09.26, see the Accessibility audit section.) Its diagonal-dash background (a deliberate nod to lane markings, this being a roads-and-streets guide) and the radial teal glow behind the logomark both animate only under `@media (prefers-reduced-motion: no-preference)`, left static otherwise. Any future full-bleed section on another page should reuse this same `isHome`-gated pattern rather than inventing a second one; it currently only exists for the homepage.

## Homepage hero background: native canvas ink-halftone effect (Item 19, 2026.09.11)

**`src/lib/theme/components/InkHalftone.svelte`** replaces `.hero-lines` (the old `repeating-linear-gradient` diagonal texture) on the homepage `Hero.svelte`, and only that layer: `.hero-glow` and `.hero-bleed`'s solid ink background are untouched, same DOM position, same stacking order. It's a `<canvas>` + `requestAnimationFrame` grid of small dots (10px spacing) whose radius swells from `0` (fully invisible at rest) up to a peak, confined to a couple of curving Bezier "road" paths drawn through the hero so the reactive shape itself reads as a street rather than a generic wipe. Built natively per the source ticket's explicit "no third-party effects bundle, no purchase" requirement, inspired by (not copied from) a paid canvas effect the user linked for reference (getdesign.md's "Ink Halftone").

**What actually drives the swelling is layered value noise, not a wave.** This went through several rounds of user feedback before landing here, each round a real lesson for any future "animated background" request:

- v1 (discrete traveling pulses along the roads, Gaussian falloff) — read as "too fast" and "too predictable," literally two clean blobs repeating on an obvious cycle.
- v2 (summed sine waves along each road's arc length) — fixed the predictability but read as one blob shape breathing in and out, and was "too slow."
- v3 (2D fractal value noise — `hash()`/`valueNoise()`/`fbm()`, several octaves at different spatial scales summed together) — this is what actually produces blobs of varying size and shape, since small- and large-scale octaves reinforce or cancel differently at every point; a single-frequency wave structurally cannot do that no matter how it's remapped or how many terms are added.
- Final tuning rounds: direction moved from a per-road flow vector to a per-octave one (three octaves biased 75–110° i.e. rightward with vertical wander, one large/slow/low-weight octave drifting the other way, so "most blobs move right, a few don't" instead of a uniform direction or a 50/50 split); scale range widened (100–720px) for a bigger min/max size spread; `NOISE_FLOOR` lowered to allow more simultaneous blobs; `PEAK_RADIUS` raised for bolder dots at full swell.

**Two real bugs hit building this, both worth remembering for any future "invisible until triggered" animated grid:**

- Setting `BASE_RADIUS = 0` (so a resting dot draws nothing) also silently broke the `prefers-reduced-motion` static frame, since that frame reused the same constant — reduced-motion users would have seen nothing at all. Fixed with a separate `STATIC_RADIUS` constant used only for that one frame.
- An early version added small random per-dot position jitter for a "hand-set halftone" look; this broke the grid's own row/column alignment, which reads as a bug (a halftone dot grid is expected to actually be a grid) rather than an organic touch. Removed entirely — position jitter and "organic" character are not the same thing; the organic quality here comes entirely from the noise-driven radius, not from perturbing the grid itself.

**Iteration reality check for future visual/motion effect requests:** none of the tuning values above (spacing, scale range, floor/ceiling threshold, direction split, speed) were derivable from the ticket or from first principles; every one of them took a round of "publish, watch it run for a few seconds in the actual dev server, compare against feedback" to land right. Budget for that when scoping a similar request rather than expecting one shot to nail speed/size/density/direction simultaneously. **Confirmed true again 2026.09.14:** `PEAK_RADIUS` bumped from `3.4` to `4.4` (Kevin's own direct edit, bolder dots at full swell), one more round of the same "the ticket/first pass gets it in the right neighborhood, the exact number still needs a live look" pattern.

## Homepage (2026.10.18)

Rebuilt from a mockup Kevin approved (`mockups/homepage-v1.html`, untracked); he plans to adjust it before publishing. **All homepage copy lives in `src/routes/+page.md`'s `<script>` block, one constant per section**, passed to one-line component tags; counts, featured media (`FEATURED_MEDIA`), the latest changelog lines and the shelf's `pageImages` come from `src/routes/+page.server.ts`. Sections, top to bottom: `Hero` (eyebrow, h1 with an italic accent part, lede, two buttons, a search button that calls `openSearch()`, and a `showcase` rendered by `StreetBeforeAfter`), `HomeGoals`, `HomeFacts`, `HomeCompare`, `HomePatterns`, `HomePositions`, `HomeTrust`, `HomeMedia`, `HomeNews`. Each section component wraps itself in `HomeSection` (`tone` plain/tint/dark, eyebrow, h2, intro, optional header link), the same full-bleed breakout as the hero; section colors are `--hs-*` custom properties so the dark band and Simplified view can swap them in one place.
- **Never use Svelte's `{name}` shorthand attribute in a `+page.md` component tag**: the markdown pipeline doesn't recognize the tag and prints it as text. Write `name={name}`. Object literals in a tag (`action={{ ... }}`) are risky for the same reason (see the nested-component notes); define a constant in the script instead.
- `StreetBeforeAfter` and `HomeCompare` draw with `PatternViewerSection` directly (not the full `PatternViewer`), with `slice: false`; both before and after are rendered in one grid cell and the hidden one is `visibility: hidden`, so the box never changes height. Any viewer data file can be shown this way.
- The homepage has no desktop `Toc` or `TocMobile` (its h2s are landing-page sections, not an article outline): `GlobalLayout` skips `Toc` when `isHome`, `PageLayout` skips `TocMobile` on `/`.
- `PatternIndexCard` has `showNumber` (default true); the homepage shelf turns it off, since the number is a position within a Pattern Index section.
- Simplified view collapses every homepage section to one 46rem column and drops the dark bands. `generate-text-pages.mjs` drops `.sba__live`, `.hc__joiner` and `.hpo__n` from the text and markdown copies.
- The facts quote figures from three Guide pages (Induced Demand ref 6, Design Speed ref 11, Ecosystem refs 1-2); if those pages' numbers change, update the homepage too.
