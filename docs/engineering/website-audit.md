## Website Specification audit, `/about/website-audit/` (2026.10.14)

**Standing goal: keep the publication passing as much of [specification.website/checklist](https://specification.website/checklist/) as practical, and keep the audit page true.** Status lives in `src/lib/audit.ts` (one row per checklist item: name, tier, status, reader-facing note); `WebsiteAudit.svelte` renders it on `/about/website-audit/` (a normal `+page.md`, About sidebar under Development) and computes every score. When a change satisfies or breaks a checklist item, update its row and `AUDIT_DATE` in the same session. Notes follow the editorial rules (no em-dashes, "the publication"); checklist item names are kept verbatim except em-dashes, which became colons. Same approach as Kevin's other two SveltePress sites (`/Users/kevinyoung/Documents/better-the-world-net`, `/Users/kevinyoung/Documents/pro-how-com`), which are the reference implementations. First pass scored 88.9% (0 items unreviewed).

What was built for it, and the rules that come with each piece:
- **Headers: `static/_headers`** (Netlify; Cloudflare passes them through). CSP, HSTS with includeSubDomains, nosniff, X-Frame-Options, Referrer-Policy, Permissions-Policy, COOP/CORP same-origin, `No-Vary-Search: params`, discovery `Link` headers, cache rules. **Any new third-party host (script, image, iframe, fetch) must be added to the CSP** or it is silently blocked on the live site. Current outside hosts: Google Analytics (after consent), Cloudflare Web Analytics (`static.cloudflareinsights.com` / `cloudflareinsights.com`, injected by Cloudflare at the edge, easy to forget because it isn't in this repo), and `yt3.googleusercontent.com` (Media card channel icons). Netlify merges a header set by two matching rules into one comma list, so don't set the same header twice for overlapping paths; keep `#` comments outside header blocks.
- **Cookie consent** (`consent.ts`, `CookieBanner.svelte`, `GoogleAnalytics.svelte`): GA loads only after Accept, built with `document.createElement` (never `{@html}` script tags); GPC counts as Decline; footer "Cookie settings" button reopens; Decline deletes `_ga` cookies. Stored in localStorage key `commonway-cookie-consent`. The banner reserves its height through `--cw-consent-height` (scroll-padding-bottom and body padding). The Privacy Policy describes all of this, plus Cloudflare and the channel icons; keep it in step.
- **Head metadata** (`PageLayout.svelte`): canonical, explicit robots (`index, follow, max-image-preview:large`, or `noindex, follow` for `utility` pages), full Open Graph/Twitter tags with a default card at `static/og/commonway-system-card.png` when a page has no `image:`. `src/app.html`: color-scheme, theme-color, favicon.ico (PNG-in-ICO, 16/32/48), SVG favicon, apple-touch-icon, manifest (`static/manifest.webmanifest`, icons in `static/favicons/`), RSS alternate, and Speculation Rules (prefetch on moderate eagerness, excluding `.md`, `/text/`, `/pagefind/`).
- **New endpoints**: `/rss.xml` (Blog feed), `/.well-known/agent-skills/index.json` and `.../commonway-system/SKILL.md` (`src/lib/server/agent-skill.ts`, digest computed at build), plus static `security.txt` (**Expires 2027-10-01: renew yearly**), `gpc.json`, `api-catalog`, `traffic-advice`, `tdmrep.json` (no reservation). New prerender-only endpoints must be listed in `svelte.config.js`'s `prerender.entries`. The sitemap now carries `image:image` entries for frontmatter images.
- **robots.txt policy (decided by Kevin 2026.10.14): AI training is allowed.** Named AI crawlers get the same rules as everyone, `Content-Signal: search=yes, ai-input=yes, ai-train=yes` inside each group, only `/pagefind/` disallowed (text-only pages and `/search/` stay crawlable so crawlers can read their `noindex`).
- **404**: adapter-static `fallback: '404.html'` + `src/routes/+error.svelte` (its own `<main id="main-content">`, noindex). Netlify serves it with a 404 status. Verified locally that the root layout's server data 404 doesn't cause a reload loop; the error page renders inside the normal shell.
- **Performance**: `inlineStyleThreshold: 100000` in `svelte.config.js` inlines all CSS (measured gain, see the comment there); `GuideDiagram` has a `priority` prop (eager + `fetchpriority="high"`, used by the four Foundations diagrams that open their pages) and serves `/diagrams/` images through a 768/1280 WebP `srcset`; `AuthorPhoto` uses the 160/480 thumbnails. View Transitions cross-fade on navigation (`onNavigate` in `GlobalLayout`, skipped for reduced motion, Simplified view, hidden tabs). The hero canvas stops drawing while off-screen.
- **Display settings panel** (`DisplaySettings.svelte`, navbar copy only) is now a `popover="auto"` opened with invoker commands (`commandfor`/`command="toggle-popover"`, click fallback calls `togglePopover()`, and a class-based fallback with the old Escape/outside-click handlers where popovers are unsupported), positioned `fixed` below the navbar, with CSS anchor positioning (`anchor-name: --cw-display-settings`) lining its right edge up with the button. The browser handles Escape, light dismiss and focus return.
- **Smaller pieces**: `text-wrap: balance/pretty` in `base.css`; a container query in `AuthorPhoto` (wrapper is `container-type: inline-size`); `inert` on `<main>` while the phone drawer is open (`GlobalLayout`); a forced-colors block at the end of `base.css` (outlines on chips/badges/cards, swatches keep their colors); `translate="no"` on Pattern/Retrofit IDs and the footer name; footer gained "Report a Problem" (consistent help).

- **Schemamap, OKF bundle, AI Catalog** (added the same day): `scripts/generate-agent-files.mjs` runs in `pnpm run build` right after `generate-text-pages.mjs` (it reads the `.md` copies). It writes `build/<page>.jsonld` (the page's own JSON-LD blocks as one `@graph`, verified identical to what the page embeds) and `build/schemamap.xml` (namespace `https://specification.website/schemas/schemamap/0.1`); `PageLayout` links both from `<head>` (`jsonldPath()` in `site.ts`). It also writes the OKF v0.2 bundle at `build/okf/`: one concept per page (`type` Pattern / RetrofitStrategy / Guide / BlogPost / Index / Page, `resource`, `tags`, `generated.at`, plus our own `pattern_id`/`pattern_status` keys), `sources` parsed from the page's `<h2 id="references">` list (evidence tier from the chip, link from the first outbound `<a>`), one mirrored `references/<slug>-<hash>.md` per distinct cited work (deduped by URL), an `index.md` per folder (no front matter except the root's `okf_version: "0.2"`), `log.md` from the Release History changelog, and `build/okf.tar.gz` via the system `tar`. **A new References list format or a renamed Release History "## Changelog" heading would break those parsers. The OKF `pattern_status` comes from `.page-head .status-badge` (`PageHeader`); it read the removed `PatternCard` until 2026.10.20 and was empty for every pattern from 2026.10.18 to then, so check a concept file after changing the header markup.** `/.well-known/ai-catalog.json` is a prerendered route listing the Agent Skill and the OKF bundle (shapes copied from specification.website's own catalog); robots.txt has the `Agentmap:` line. DNS-AID: an HTTPS record at `_index._agents` in Cloudflare (priority 1, target `commonwaysystem.org`, `alpn="h3,h2" port=443`), live and DNSSEC-validated 2026.10.14. **macOS's bundled `dig` (9.10.6) doesn't know the HTTPS record type** and silently looks up a domain named "HTTPS" instead, so `dig HTTPS ...` shows nothing; query `dig TYPE65 _index._agents.commonwaysystem.org @1.1.1.1 +dnssec` (the answer is hex; `ad` in the flags means DNSSEC validated) or use a newer dig from Homebrew.
- **`_headers` gotcha found the same day:** a folder rule like `/patterns/*` also matches the pattern *pages* (HTML, `.md`, `.jsonld`), which briefly gave them a month-long cache; it's now per image extension. And Netlify joins a header that two matching rules both set into one comma list (invalid for Content-Type, CORS), so `/.well-known/` files are listed one by one. Before adding a rule, check overlaps: for every file in `build/`, collect the headers from all matching `_headers` rules and flag any name set twice (a 20-line Python check).

**How this release was verified (reuse it; the tools are now saved in `scripts/qa/`, see Commands):** a Node server that mimics Netlify (serves `build/`, applies `static/_headers` including the CSP, gzip, `404.html` with status 404) plus puppeteer-core, axe-core and Lighthouse borrowed from `pro-how-com/scripts/qa/node_modules` (via `createRequire`) driving the local Google Chrome headless. That runs axe on many pages in light/dark at 1280 and 375 in one go, captures console warnings (CSP violations and hydration failures show up there), and runs Lighthouse mobile. Compression matters for Lighthouse: an uncompressed local server makes every page look 2x slower. Lighthouse also flagged CLS of about 0.05 from `TocMobile` appearing after hydration (under the 0.1 threshold, left alone). The PageSpeed Insights API has a small shared daily quota and was exhausted.

**Cloudflare settings:** Kevin turned on DNSSEC, CAA records, Crawler Hints (IndexNow) and Early Hints on 2026.10.14 (all Pass on the audit page; Cloudflare adds its own CA records once any CAA record exists, so don't add more; the DS record at .org was confirmed later the same day). Redirect-By: a Cloudflare Response Header Transform Rule ("Redirect-By on redirects", `http.response.code in {301 302 307 308}`, sets `Redirect-By: Netlify`) because all the redirects come from Netlify, which can't add headers to them; verified live 2026.10.14. It may not cover a redirect Cloudflare generates itself. Still left (Fail on the audit page): external uptime monitoring; caching HTML at the edge might also lower live LCP.
