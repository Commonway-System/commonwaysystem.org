# Search, site map, text-only and markdown pages, images and thumbnails

Moved from CLAUDE.md on 2026.10.20 without rewriting. Words like "above" and "below" may now point to another file in `docs/engineering/` or `.claude/rules/`; the index at the end of CLAUDE.md lists them all.

## Commands (continued)


**Standing rule: any time an image is added or replaced for the site, run `pnpm run thumbs` and commit the new `thumbs/` files.** That means a new file in `static/patterns/`, `static/media-assets/`, `static/photos/` or `static/diagrams/` (Pattern and Retrofit illustrations, Media Gallery previews, the author photo, Foundations diagrams, which get 768/1280 px copies instead of 160/480), or a local `image:` in any page's frontmatter (a blog post's featured image, say). Search results and the Pattern, Retrofit and Media cards show those small copies, not the 1 MB originals; the script is safe to re-run (it skips thumbnails that already exist and remakes ones whose source changed) and `pnpm run build` warns `Thumbnail missing for ...` if one was forgotten (the site then falls back to the full-size image, which works but is heavy). Do this in the same session that adds the image, and mention the thumbs in the commit. Details: "Featured images and thumbnails" near the end of this file.

## Markdown versions of every page, for AI/LLM readers (2026.09.26)

`scripts/generate-text-pages.mjs` (the same post-build step as the text-only pages) also writes `build/<route>.md` for every page (`/patterns/foo/` -> `/patterns/foo.md`, homepage `/index.md`; `markdownPath()` in `src/lib/site.ts` is the one routing rule, the script has its own copy). It starts from the same cleaned `<main>` (`cleanMain(main, mapHref)`, link mapper differs: markdown links become absolute `SITE_URL/...md` URLs so a file works read on its own), then `turndown` + `turndown-plugin-gfm`. Details worth knowing: a small YAML front matter (title, url, id, description, updated) is built from the page's own `<title>`, meta description and JSON-LD; `<sup><a href="#ref-N">` citation badges become `[N]` (placeholder `@@CN@@` survives turndown's escaping); tables whose cells hold block content (the `GuidanceTable`) are flattened to one h3 per row and h4 per column by `flattenComplexTables()`, simple tables stay GFM tables; a card that is one big link (media cards) links its heading instead; modal-hierarchy `>`/`=` separator spans use placeholders for the same escaping reason. Discovery: `<link rel="alternate" type="text/markdown">` in `PageLayout.svelte`'s head, `llms.txt` bullets point at the `.md` URLs, and `static/_headers` serves `/*.md` as `text/markdown` with `X-Robots-Tag: noindex`. `svelte.config.js`'s prerender `handleHttpError` ignores `.md` 404s for the same reason it ignores `/text/` (files exist only after the post-step). Like `/text/`, the `.md` files and the `_headers` rule do not exist under `pnpm run dev`; the `_headers` splat (`/*.md`) is unverified until deployed (check with `curl -I https://commonwaysystem.org/index.md`). `build/llms-full.txt` (same script) concatenates every page's markdown (home first, then by route, each led by a `Source: <url>` line, front matter dropped) and is linked from `llms.txt`. Not built: `Accept: text/markdown` negotiation on the HTML URLs (needs a Cloudflare Worker or Netlify edge function).

## Site search (2026.09.26)

**Engine: Pagefind, chosen for a static deploy and a Netlify-minutes constraint** (the owner does not want extra build cost; indexing 165 pages takes ~0.2 s, so it adds nothing measurable). Runs in the browser, index chunks load lazily, nothing typed leaves the browser (which keeps `/about/privacy-policy/`'s "no other tracking" true; do not swap in Algolia/DocSearch). SveltePress's own search is a default-theme feature and `@sveltepress/theme-default` is not installed, so this is hand-built on Pagefind's JS API instead of Pagefind's Component UI (chosen so the UI inherits our tokens and every Display setting without fighting a third-party stylesheet; the Component UI's theming/a11y was not verified).

**Build:** `pnpm run build` now ends with `scripts/build-search-index.mjs` (Pagefind Node API, `includeCharacters: '+'` so "2+1 road" works) writing `build/pagefind/`. It indexes every page whose `<main>` carries `data-pagefind-body` (`PageLayout.svelte`; Pagefind skips every page without it, which is what keeps `/text/` and `/search/` out), plus one custom record per Media item read from `src/lib/data/media/entries/*.ts` (Node 24 type-stripping imports them; a media result's URL is `/media/?q=<title>`, which `MediaGallery.svelte` reads into the Gallery's own search store). Failures are logged loudly but do not fail the build (the site still deploys; search shows "couldn't load").

**What is and isn't indexed (markup in `PageLayout.svelte` unless noted):** section and Pattern-type filters (`search-meta.ts`, one empty marker `<span>` per filter/meta pair because one `data-pagefind-meta` attribute holds one pair), the Pattern ID as a `hidden` weighted span (the ID card itself is `data-pagefind-ignore`; `[hidden]` is dropped by the text/markdown generators), H1 weight 10, and `data-pagefind-ignore` on page meta/legal rows, `PageNav`, `TocMobile`, `RelatedMedia`, the Media Gallery grid and filters (so media items appear only as their own results), and the heading "#" anchors (`heading-anchors.ts`). Add `data-pagefind-ignore` to any new repeated chrome inside `<main>`, or it pollutes excerpts.

**UI:** `search.ts` (store `searchOpen`, lazy `loadPagefind()` with a variable-URL `import()` so Vite doesn't bundle it, `searchSite()`), `SearchPanel.svelte` (input, filter checkboxes, live count, results; used by both mounts, `variant: 'dialog' | 'page'`; the page variant mirrors state into `?q=&section=&class=` via `replaceState`), `SearchDialog.svelte` (native `<dialog>` + `showModal()`, mounted once in `GlobalLayout`, closes on navigation), `SearchButton.svelte` (navbar, hidden below 940px), a Search button at the top of the mobile drawer in `Sidebar.svelte`, and `src/routes/search/+page.md`. **Ctrl/Cmd+K only: no single-character shortcut, on purpose (WCAG 2.1.4).** The `utility: true` frontmatter flag (used by `/search/`) means: `noindex` meta, no Pagefind body, no text-only link, no markdown alternate, and it is filtered out of `sitemap.xml` and `llms.txt` (`PageMeta.utility` in `content.ts`); `generate-text-pages.mjs` skips any page with a `robots noindex` meta.

**Dev:** `vite.config.ts`'s `devSearchIndex()` plugin serves the last build's `build/pagefind/` at `/pagefind/` under `pnpm run dev`, so search works in dev after one build (results lag recent edits).

## Human site map, `/about/sitemap/` (2026.09.26)

Built at prerender time, never hand-listed. `src/routes/about/sitemap/+page.server.ts` calls `buildSiteMap()` (`src/lib/server/sitemap-tree.ts`) with the theme options (`virtual:commonway/options`, i.e. the navbar and manual sidebar from `vite.config.ts`) and `getSitePages()`; `SiteMap.svelte` renders `page.data.siteMap` (types in `sitemap-types.ts`, kept out of `$lib/server` so the client component can import them). Sections follow the navbar order; groups, order and link labels come from the sidebar tree; Pattern/Retrofit IDs appear beside links (`PageMeta.patternId`); Blog posts (no sidebar) are listed newest first by `date`; Media is one link (media items are data records, search covers them). **Any page found on disk but not reached by the navbar/sidebar is listed under "Other pages" and logged as a `Site map:` warning in the build output**, so a page forgotten in `vite.config.ts`'s sidebar can't silently vanish; treat that warning as a to-do (add the page to the sidebar). Utility pages (`utility: true`, currently only `/search/`) are not part of the map. The page's "Other ways to browse" list is static markdown (Search, `/text/all-pages/`, `/sitemap.xml`, `/llms.txt`, `/llms-full.txt`); `svelte.config.js` ignores the prerender 404 for `/llms-full.txt` (written post-build). Linked from the About sidebar (right after Overview), the About overview, the footer row (`PageLayout.svelte`, whose nav is now labeled "Footer"), and both the search dialog and `/search/` (`SearchPanel.svelte`'s "Prefer to browse?" line). `generate-text-pages.mjs` no longer counts noindex utility pages as link targets when rewriting links.

## Featured images and thumbnails (2026.09.26)

**One source of truth per page: an optional `image:` in the page's frontmatter** (a site-relative path like `/patterns/net-grd-01-grid.png`; full-size original lives in `static/`). It replaced the hand-typed `image=` prop on each card in `patterns/+page.md` (27 were migrated; `PatternIndexCard`/`RetrofitIndexCard` still accept `image` as an override, and the Brand Guide demos use it). `getSitePages()` exposes it as `PageMeta.image`; `src/routes/patterns/+page.server.ts` and `src/routes/retrofits/+page.server.ts` build a `pageImages` route-to-image map at prerender time and the two index cards read `page.data.pageImages[href]`, falling back to `pattern-placeholder.svg` (the classification/scale color overlay is unchanged). The same field feeds `og:image`, `twitter:card`/`twitter:image` (PageLayout head; only when set), `image` in each page's JSON-LD (`schema/page.ts`), and the search result thumbnail. Blog posts and Retrofit Strategies use the same `image:` field; none have one yet (placeholder until they do).

**Adding featured images Kevin drops into `static/patterns/` (2026.10.23, nine element pages):** find each page with `grep -rl "^patternId: <ID>" src/routes`, add `image: /patterns/<file>` after `date:` in the frontmatter, run `pnpm run thumbs` (it also makes a `-1280.webp` for each), add one changelog line naming the pages, then build and axe the pages plus `/patterns/`. Files named `.png` that are really JPEG data are common here (24+ of them) and display fine; leave the extension. Do fix a typo in a filename (`verticle` became `vertical`), since the name becomes a public URL. Alt text comes from the title automatically ("Overview illustration of <title>").

**Thumbnails: `pnpm run thumbs` (`scripts/make-thumbs.mjs`, `sharp`)** writes `<dir>/thumbs/<name>-160.webp` and `-480.webp` next to every raster image in `static/patterns/` and `static/media-assets/` plus any local `image:` named in a page's frontmatter. The naming rule is `thumbUrl()` in `src/lib/thumbs.ts`, so components ask for the conventional path without knowing whether it exists; every `<img>` that uses one has an `onerror` fallback to the original. **Thumbnails are committed** (deliberately not generated on Netlify, to keep build minutes down); `pnpm run build` ends with `make-thumbs.mjs --check`, which only warns. 160px is for search results, 480px for the index and gallery cards (they were shipping ~1 MB originals before; the 54 pattern thumbnails total under 1 MB). Re-run after adding or replacing ANY image (see the standing rule under Commands).

**Media previews are self-hosted** (decided 2026.09.26, so search can show them on any page without contacting YouTube/Squarespace and the "search sends nothing anywhere" promise stays true): 21 files, `static/media-assets/med-NNN.jpg` at 640px wide, originally downloaded from the creators' own thumbnails. They belong to the creators; each item still links back to its source, and a copy should be removed if a creator asks. Channel/show logos (`sourceIcon`) are self-hosted too since 2026.10.14: 96px JPEGs in `static/channel-icons/<channel-slug>.jpg`, referenced as `/channel-icons/<slug>.jpg` (hotlinked ones intermittently failed to load). A new channel needs its icon downloaded there. The `yt3.googleusercontent.com` CSP allowance, the audit rows and the Privacy Policy were updated to match, and `Cross-Origin-Embedder-Policy: credentialless` was added to `_headers` (COEP row now Pass; verified locally: `crossOriginIsolated` true, search, images and GA-after-Accept all load; the Cloudflare beacon can only be checked live, and COEP `credentialless` is the thing to revert first if a new cross-origin embed ever breaks). **Any new cross-origin image/script must work under COEP credentialless (no-cors loads are fine; iframes need CORP/COEP on their side).**

**Search results** (`search.ts` `thumbFor()`, `SearchPanel.svelte`): Patterns, Retrofits, Blog and Media results always get a thumbnail (their own image, else a placeholder); **any other page (Guide, About, Reference, Home) gets one only if it sets `image:` in its frontmatter, and no placeholder otherwise.** PageLayout writes the image into a Pagefind meta key named `thumb` (media records get it from `build-search-index.mjs`); it is deliberately NOT called `image`, because Pagefind auto-fills `meta.image` with the first `<img>` on every page, which would give pages like the Brand Guide a thumbnail nobody chose. Pattern and Retrofit thumbnails are white-background line art, so they sit on the classification's `-rural` ramp tint with `mix-blend-mode: multiply` (a Retrofit borrows its Pattern peer's ramp, as its index card does); photos are untinted. Missing image: Patterns/Retrofits show `pattern-placeholder.svg`, Blog/Media `media-placeholder.svg`. Thumbnails are decorative (`alt=""`, `aria-hidden`), hidden in Simplified view. In the dialog the filter checkboxes now sit in a collapsed "Filters" disclosure so results stay in view; the `/search/` page keeps them open.

## Session practice notes from the search, site map and thumbnails work (2026.09.26)

- **Node 24 is required for the build** (Netlify uses `NODE_VERSION=24`; `build-search-index.mjs` and `make-thumbs.mjs` import `.ts` files directly via Node's type stripping, e.g. `src/lib/thumbs.ts` and the media entries). Don't add TypeScript syntax that type stripping can't erase (enums, parameter properties) to those imported files.
- **Any new content collection or per-page data must be wired into three places, not one:** Pagefind (`PageLayout.svelte` markers / `build-search-index.mjs` custom records), the site map (`sitemap-tree.ts`; automatic if it is a page in the sidebar), and `llms.txt`/`sitemap.xml` (automatic via `getSitePages()`, filtered by `utility`). Check all three when adding a section, or it will be reachable but unsearchable or unlisted.
- **New repeated chrome inside `<main>` needs `data-pagefind-ignore`** or it pollutes search excerpts; a new component that is one big link should link its heading instead when it lands in the markdown version (see `toMarkdown()` in `generate-text-pages.mjs`).
- **Do not add a single-character keyboard shortcut** (WCAG 2.1.4). Modifier combinations (Ctrl/Cmd+K) are fine.
- **Verifying dialogs and JS-driven UI with axe:** the iframe recipe above works for a dialog too: after load, click the trigger (`.sb` on desktop; on phone width click `.navbar__menu-btn` then `.sidebar__search`), set the input's `value` and dispatch an `input` event, wait ~2s for results, then run axe. Also run it with `data-text-size='largest'`, `data-contrast='high'`, `data-view='simple'`, `data-focus='enhanced'` set on `<html>`. **Do not edit any file while a scan runs** (Vite hot-reloads the tab and wipes `window.__results`), `pnpm run build` kills the dev server (call `preview_start` again; if 5173 is taken it picks another port, e.g. 5174), and `read_console_messages` returns stale errors from before a fix, so confirm a fix by testing behavior or fetching the module source rather than trusting old console lines.
- **Pagefind gotchas:** one `data-pagefind-meta`/`-filter` attribute holds exactly one `key:value` pair (use one empty `<span>` per pair); Pagefind auto-fills its own `meta.image` from the first `<img>` on every page (that is why the field we read is named `thumb`); filter counts are only correct after `pf.filters()` has loaded; filter values with multiple selections need `{ any: [...] }`.
- **SvelteKit:** `replaceState()` from `$app/navigation` throws before the router is initialized (guard it, as `SearchPanel.svelte`'s `syncUrl` does); `page.url.searchParams` can only be read in effects/handlers on prerendered pages, not during render.
- **Open accessibility gaps added by this work:** the search dialog, `/search/`, and the Site Map have been axe-scanned in both themes at desktop and 375px and in the Display settings modes, but not tested with a screen reader or in forced-colors mode; the search dialog's arrow-key result navigation is custom (links, not a listbox), so it is a likely place for a real assistive-technology check.
