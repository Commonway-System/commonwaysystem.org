# Media Gallery and Related Media

Moved from CLAUDE.md on 2026.10.20 without rewriting. Words like "above" and "below" may now point to another file in `docs/engineering/` or `.claude/rules/`; the index at the end of CLAUDE.md lists them all.

## Media Gallery & Related Media (2026.09.04)

**A new content shape, distinct from Patterns/Retrofit Strategies/Guide pages, built for this feature: data records instead of full content pages.** Patterns, Retrofit Strategies, and Guide pages are each a hand-authored `+page.md` with real prose and their own route; there is no queryable collection behind them, the "index" pages are hand-typed lists of card components. Media items have no route of their own and need to be filtered/sorted/cross-referenced, so they're stored as one TypeScript file per entry under `src/lib/data/media/entries/` (e.g. `med-001.ts`, exporting a `default` object typed against `MediaItem` in `src/lib/data/media/types.ts`), globbed at build time by `src/lib/data/media/index.ts` (`getMediaItems()`, `getMediaItemsFor(pageId)`) the same `import.meta.glob` mechanism `$lib/server/content.ts` and `$lib/theme/blog.ts` already use for `+page.md` frontmatter. `.ts` over `.json`: identical build-time-only performance either way, but `.ts` gets checked by `pnpm run check` (catches a typo'd `endorsementStatus` or a missing field at edit time; JSON has no schema enforcement). **This is the pattern to reuse for any future data-record content type** (not a full page) that needs filtering or cross-referencing, the same way Patterns/Retrofits are the pattern to reuse for a future full-page content type.

**`MediaItem` schema** (`src/lib/data/media/types.ts`): `id` (permanent, e.g. `MED-001`, never reused), `type` (`video | podcast | article`), `title`, `url`, `sourceName`, `sourceIcon` (optional — full external URL to hotlink, or a local `/`-prefixed static path; omit for a generic Lucide fallback icon keyed to `type`, see `MediaCard.svelte`), `image` (optional; as of 2026.09.26 a SELF-HOSTED local path, `/media-assets/med-NNN.jpg`, never a hotlink: the 21 existing previews were downloaded once and resized to 640px wide; omit for the shared placeholder `static/media-assets/media-placeholder.svg`), `blurb` (how the item relates to CS content, not a neutral summary), `endorsementStatus` (`aligned | context-only | counterexample`, always rendered as a uniform neutral pill with no color-coding, a deliberate house rule), `patternTaxonomyTags` (reuses the Local/Collector/Arterial/Freeway vocabulary), `mediaTags` (locked vocabulary: `Case Study`, `Explainer`, `Interview`, `News/Advocacy`, `Historical` — do not add a value without confirming first), `relatedTo`, `dateAdded` (ISO 8601). 45 entries exist as of 2026.10.14 (21 as of 2026.09.14, added across four batches; `MED-022`-`MED-045` are the fifth, below): `MED-001` (Not Just Bikes, continuous sidewalks); `MED-002`–`MED-005` (City Beautiful ×3, BicycleDutch ×1); `MED-006`–`MED-020` (Global Cycling Network, Not Just Bikes, City Beautiful, Safe By Design, Streetcraft, Road Guy Rob); `MED-021` (Strong Towns, "The Key to Slowing Traffic is Street Design, Not Speed Limits," the first `type: article` entry, tagged to `/guide/design-speed/`) — see the batch notes below for what each round involved. `type: 'article'` items get the same generic-fallback-icon treatment as video/podcast (a Lucide file-text icon in `MediaCard.svelte`) when `sourceIcon` is omitted; a real channel/publication avatar (even a plain text monogram like Strong Towns' "ST" logomark) still renders fine as a hotlinked image, no special-casing needed for a non-photographic icon.

**`relatedTo` accepts Pattern IDs, Retrofit Strategy IDs, _and_ trailing-slashed route paths** (e.g. `/guide/legal-planning-mechanisms/`) in the same array — extended beyond the original ticket's "Pattern IDs and/or Retrofit Strategy IDs only" spec once it became clear Related Media was also supposed to render on Guide/About pages, which have no ID of their own. When adding a future media item tagged to a Guide or About page, use that page's own route path in `relatedTo`, not an invented ID.

**Components** (`src/lib/theme/components/`): `MediaCard.svelte` (the card itself — featured image with a media-type icon overlay and an endorsement-status pill, both on solid `--cw-ink-fixed`/`--cw-paper-fixed` tokens rather than a translucent overlay, since a translucent fill's contrast would depend on whatever photo sits underneath, the same guaranteed-contrast reasoning as `PatternIndexCard`'s number circle; title; source line with its own icon-or-fallback; blurb; whole card is one external link with the site's standard `externalLinkAttrs`/opens-in-new-tab treatment applied by hand, since this is a hardcoded link from data, not markdown, same as `Navbar`/`SidebarGroup`/`PageLayout`'s edit link). `MediaGallery.svelte` (the `/media/` results grid + count, 3-column, using the shared `.pattern-index-grid` class). `MediaFilters.svelte` (the search/checkbox/sort control panel, laid out as a vertical stack). `RelatedMedia.svelte` (the boxed, self-hiding section — renders nothing at all if no media item's `relatedTo` matches the given page id — used on Pattern pages, Retrofit Strategy pages, and Guide Foundations/Make It Happen/`about/commonway-system/` pages; its card grid is its own `.related-media__grid` class, deliberately **not** `.pattern-index-grid`, capped at 2 columns rather than 3, a later explicit user request to keep the Gallery's own 3-column grid untouched while narrowing the boxed callout's grid). Icons are 3 more Lucide icons (circle-play, headphones, file-text, plus mic and video as source-icon fallbacks), same ISC-licensed inline-`{@html}` convention as `ModalHierarchyPill.svelte`; see `/THIRD-PARTY-NOTICES`.

**`/media/` uses a custom 2-column layout, not the sitewide 3-column sidebar/content/toc shell** — a later, explicit user request. `GlobalLayout.svelte` gains an `isMedia` route check (`page.url.pathname === '/media/'`, same mechanism as the homepage's existing `isHome`), which hides the sidebar (`.shell--media :global(.sidebar) { display: none }`, same technique `.shell--full` already uses for the homepage) and swaps the toc-column slot from `<Toc />` to `<MediaFilters variant="desktop" />`. The content column absorbs the sidebar's freed width (`grid-template-areas: 'content toc'` with only 2 tracks instead of 3), and `/media/+page.md` sets `wide: true` so `.cw-content` actually uses the wider column instead of staying capped at the 46rem prose measure. **Because `MediaFilters` (in the toc grid slot) and `MediaGallery` (in the content grid slot) are rendered as separate siblings by `GlobalLayout`, not nested,** they can't share reactive state through props — filter state (search text, selected type/source/topic checkboxes, sort order) lives in a new `src/lib/theme/media-filters.ts` module of `writable` stores, the same cross-component-state mechanism `layout.ts` already uses for `sidebarOpen`/`pageAnchors`/`isDark`, not Svelte 5 runes. If a future page needs a similarly custom (non sidebar/content/toc) shell, say so explicitly rather than assuming Claude will infer it — `isHome` and `isMedia` are the only two departures from the default 3-column template so far, and both required a `GlobalLayout.svelte` change, not just a page-level one.

**`MediaFilters.svelte` mobile redesign (2026.09.04, two follow-up rounds after initial ship):** the desktop 2-column layout above is only half the story below 940px. Round 1 found a real bug: the original single always-`position: sticky` implementation stayed pinned to the top of the viewport in the mobile stacked layout too, so scrolling made it visually overlap the results grid scrolling underneath it (sticky only makes sense next to a much taller sibling column, the desktop case). Round 2 was a design request: a permanently-expanded filter panel was also eating most of the mobile screen before any results were visible, and the user wanted it collapsed by default on mobile with no toggle at all on desktop, repositioned to sit just before the results count/grid rather than above the page title.

The fix ended up as **two small mounts of the same component, not one instance repositioned with CSS**, via a `variant: 'desktop' | 'mobile'` prop: `variant="desktop"` renders a plain `<aside>`, always expanded, no toggle affordance, CSS-hidden below 940px — this is what `GlobalLayout.svelte` mounts in the toc-column slot, unchanged in spirit from the original design. `variant="mobile"` renders a real `<details>`/`<summary>` disclosure, collapsed by default (no `open` attribute, works with no JS via native browser semantics), CSS-hidden at 940px and up — this is mounted separately, inline in `/media/+page.md`'s own markdown between the intro paragraph and `<MediaGallery />`, landing it exactly where a reader expects a filter control: right before the results, not above the title. Both instances read/write the same `media-filters.ts` stores, so they're never out of sync, just two different rendering locations for the same underlying state. **The reason it's two mounts instead of one repositioned element:** the desktop slot (a `GlobalLayout`-level grid sibling) and the mobile position (a descendant inside the page's own content column, itself nested in a completely different grid container) are genuinely different DOM subtrees — no CSS mechanism (`order`, `grid-area`, positioning) moves an element between two unrelated grid contexts. If a future page needs "different content/position per breakpoint, sharing one piece of state," this two-small-mounts-plus-shared-store pattern is the one to reuse, not a single repositioned element.

## Media Gallery filters and cards (2026.10.17)

- **Filter column** (`MediaFilters.svelte`, mounted twice: desktop toc slot and phone `<details>`, same stores in `media-filters.ts`). Search box and Sort are plain fields, Media type is a single row of checkboxes, and **Source, Pattern, Retrofit Strategy and Topic are `MediaFilterList.svelte`**: a native `<details>` (closed by default, `(N selected)` and a chevron in the summary, ids made unique with `$props.id()` because two copies mount), a "Find a ..." box, a scrolling checklist with counts and a CSS-only scroll shadow (same technique as the Display settings panel and tables), and a clear link. Adding another long filter group means a new store, an options array, one `<MediaFilterList>` tag, and one line in `MediaGallery.svelte`'s filter. Pattern/Retrofit options come from the IDs in every item's `relatedTo` (route paths excluded) labelled with the titles in `page.data.mediaPages`, which `/media/+page.server.ts` builds; so a page with media but no title in that map falls back to its bare ID. **Within a group values are OR, across groups AND** (Boulevard plus the road diet shows 0 because nothing is tagged to both). Measured column height: about 560px closed, 1,300px before the collapse, 2,700px with the original flat Source list.
- **Search box** matches the media ID, title, blurb, source name, and each related page's ID and title (`MediaGallery.svelte` `haystack`). Site search (`build-search-index.mjs`) shows `MED-NNN · Type · Channel` on media results and indexes the ID.
- **Sort** has eight options (`MediaSort` type); every sort falls back to ID order because a batch shares one `dateAdded`.
- **Card image height bug (fixed):** `.mc__image` is `flex: none`, `overflow: hidden`, 16:9, and the `<img>` is `position: absolute; inset: 0; object-fit: cover`. Without that a portrait image grew the box (percentage height on an img inside an aspect-ratio box resolves against content) and a long blurb squeezed it in the flex column. After changing card CSS, measure `.mc__image` heights across the Gallery and a carousel page (all should be identical per viewport).
- **Related Media edge fades** reach 6px past the frame on every side because the track bleeds out by its negative margin; keep the two numbers in step.
- **Working method that held up:** build, serve `build/` with `node scripts/qa/netlify-like.mjs build 5180` in the background, then `qa.mjs` plus a small puppeteer-core script (borrow it with `createRequire('/Users/kevinyoung/Documents/pro-how-com/scripts/qa/node_modules/package.json')`, set input values by dispatching `input` events, click checkboxes inside `evaluate`) to check behavior and measure geometry. `qa.mjs --setup="document.querySelectorAll('details').forEach(d=>d.open=true)"` scans collapsed groups open. **Don't `git stash` to compare a "before" build:** it stashes every uncommitted file, so the build is of an old commit, not of one change.
- **Media batch notes** live with each batch above (MED-141 to MED-155 is the eleventh). The table's `Source` for a video may name the agency rather than the uploader; `mqdefault` is the clean 16:9 fallback when `maxresdefault` doesn't exist; an image URL from a table can 404 while the page's own `og:image` works.
