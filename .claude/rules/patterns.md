## Architecture (continued)


**Pattern ID scheme (corrected to nine prefixes, 2026.08.31):** `[PREFIX]-[CTXCODE]-[##]` with an optional trailing `(DENSITY)` suffix (`UND`/`RRL`/`SUB`/`CPT`/`URB`/`COR`), e.g. `LOC-BBG-12`. `PREFIX` encodes Scale: `NET` (Network), `CDR` (Corridor), `FAC` (Facility), and `ELM` (Element) are flat, non-subdividing prefixes, one per Scale; `LOC`/`COL`/`ART`/`FRE` (the four Functional Classifications) and `INT` (Intersections & Crossings, cross-cutting, its own top-level code rather than nesting under one classification) are the five prefixes at the Segment/Intersection scale, the only Scale that subdivides by Functional Classification. `CTXCODE` is a hand-designed three-letter mnemonic; each classification's baseline/default entry uses `DEF` (not the classification's own letters). Two different prefixes can legitimately share the same `CTXCODE` (`ELM-TRB-23` Traffic Barrier and `INT-TRB-02` Turbo-Roundabout), not a bug, same precedent as `COR`/`COL`. **The number is two digits, assigned once per Typology within its prefix in first-added order, and is never reassigned or reordered to match display/alphabetical order later** — this is the rule that broke twice during scaffolding (see `src/routes/patterns/+page.md` for the current full mapping, and the pattern-pages project memory for the format's version history if a stale mapping ever surfaces again). The `(DENSITY)` suffix is added only once a second page exists for the same Typology at a different density tier; omit it otherwise, don't pre-add it. **106 patterns are live as of the 2026.08.31 batch build-out**, every one of them with a real `+page.md`, no more descriptive-only placeholder tables: 4 Network (`src/routes/patterns/network/`, deliberately singular, unlike every other category folder below — matches the route convention given when this batch was scoped, not a typo to "fix" into `networks/`), 6 Corridor (`corridors/`), 13 Local + 7 Collector + 8 Arterial + 4 Freeway + 11 Intersections & Crossings (43 total Segment/Intersection, `local-streets/`, `collectors/`, `arterials/`, `freeways/`, `intersections/`), 10 Facility (`facilities/`), and 43 Element (`elements/`). This batch resolved every previously-open item: the three formerly "under review" Typologies now have real pages and Pattern IDs (Downtown Thoroughfare `COL-DTH-07`, Commercial Arterial `ART-CAR-07`, Parkway `ART-PKY-07`, renumbered from `ART-PKY-08` on 2026.09.02, see below), and the Pattern Index's old "On the Horizon" descriptive tables and "Under review" bullet list are both gone, their contents built out into real pages instead. Two names from the original "under review" wording were deliberately never built: Avenue and the Downtown One-Way/Two-Way Street cluster are not real patterns (Downtown One-Way is just an instance of the existing One-Way Street, `ART-OWS-06`; Avenue was dropped from consideration). Each pattern page's numeric suffix is now also duplicated into a `patternId` frontmatter field (see JSON-LD note above), so the two must be kept in sync by hand if the ID scheme ever changes.

## Layered guidance table, `GuidanceTable` (2026.09.25)

**Live on two pages so far: `patterns/collectors/default/` (COL-DEF-01, the trial run) and `patterns/collectors/rural-collector/` (COL-FTM-02).** It is the intended standard section for every Local, Collector, Arterial, and Intersections & Crossings pattern page, but not rolled out beyond those two. Placement: a `## Layered guidance across sources` section immediately **before** `## Design notes`. Don't add an empty or placeholder table to any other page: each one needs real researched rows first, same "absent is more honest than empty" rule as the Illustration section.

`src/lib/theme/components/GuidanceTable.svelte` takes `rows` (and an optional `columns`, defaulting to the exported `defaultGuidanceColumns`: Commonway System first and highlighted, then Federal / State baseline, NACTO enhancement, Complete Streets layer, Dutch / Sustainable Safety). **Rows are free-form data, not a fixed schema**: Collector Default's nine rows (travel lane width, number of travel lanes, bicycle facility, pedestrian facility, speed management, intersection treatment, separation / buffer, on-street parking, property access) are the expected starting set for most patterns, but each pattern adds or drops rows as its own research turns up (or fails to turn up) sources. Each row is `{ label, cells }` with one cell per column in column order (Commonway System cell first); each cell is `{ summary, content }`. `summary` is a very short line (prescriptive in the Commonway System column, e.g. "10 ft lanes."), `content` is the full wording as segments: plain strings, `{ cite: N }` badges, `{ href, label }` internal links, `{ note }` muted open-gap text, `{ tier: { label, body } }` a labeled block (used wherever an answer differs by speed tier or connection type, e.g. "Below 45 mph" / "45 mph and above"; tiers can nest), and `{ table: { head, rows } }` a small nested table. Rendered as native `<details>` per cell (keyboard-accessible, works without JS; collapsed cells stay collapsed in print), plus row-header and "Expand all" toggles; wrapped in the same `.cw-table-wrap` structure as markdown tables so the sitewide scroll shadow and overflow hint apply. **The highlighted column is exactly twice as wide as the others**, via `<colgroup>` percentages (11% row labels; calc() widths on `<col>` are ignored by browsers, and a `<colgroup>` inserted via string replace can land in the wrong `<thead>`, the nested-table snippet has one too, check the DOM).

**Author the data in the page's `<script>` block and pass `rows={guidanceRows}`**, not inline in the tag: a multi-line object-literal prop breaks CommonMark's HTML-block recognition (see the nested-component notes above). Cells are structured segments, not markdown, for the same nested-slot reason. Small script helpers (`na(why)`, `unspec`, `gap(why)`) keep repeated "Not applicable / Not specified / Not researched" cells short. Citation numbers continue the page's own `## References` list; reuse an existing number rather than re-citing. **Mark open gaps in the cell itself** (a `{ note }` or a "Not researched." summary) rather than guessing; several cells on both pages are deliberate gaps.

**`SpeedTerrainTable.svelte`** renders a small data-driven table (head, rows of `{ text, retrofit? }`, `retrofitHref`) inside `SpeedLimitSection`'s slot, where a markdown table would not parse. Used on Rural Collector for the terrain-by-volume design-speed table; pair it with `SpeedLimitSection`'s `stacked` prop so it gets full card width. Don't embed that table a second time in the guidance table's Speed row (ticket rule: the speed box is where readers look first).

**Working with tickets that bring their own numbering and sources (lessons from these rounds):** (1) A ticket's reference numbers follow its author's numbering, not the page's live one; when a ticket says "add references 7-15" and the page already has a 7, append after the highest live number and remap the ticket's in-text citation numbers, never renumber live references. (2) A ticket often omits URLs for citations it asks for, or names a source it read secondhand; find real primary URLs (WebSearch, then confirm in the browser tool), and where a claim can't be verified (a paywalled AASHTO table, a PDF the fetch tool can't read), cite what was verified, word the cell to match, and flag the gap in the final report rather than passing it as confirmed. WebFetch cannot read most PDFs; `pdftotext` isn't installed, but a small Python `zlib` stream-extraction script over the saved PDF works for text-layer PDFs. (3) The dev server (`preview_start`) stops after a `pnpm run build`; restart it before browser verification. Screenshots taken after a JS scroll can come back blank in the Browser pane; verify with `javascript_tool` (computed styles, DOM queries) instead.
