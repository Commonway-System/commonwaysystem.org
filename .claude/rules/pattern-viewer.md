# Pattern viewer

Moved from CLAUDE.md on 2026.10.20 without rewriting. Words like "above" and "below" may now point to another file in `docs/engineering/` or `.claude/rules/`; the index at the end of CLAUDE.md lists them all.

## Pattern viewer (2026.10.16, all six build steps done)

**Planned with Kevin in one session; the decisions are settled, don't re-open them.** A box right after the Pattern ID card (or the Retrofit ID card; both are `PageHeader` since 2026.10.18) on every pattern and Retrofit page, replacing the old `Illustration` section (whose content is being dropped). Build order: (1) data types and parent shell, done; (2) cross-section and plan SVG renderers, with computed "what changed" highlights, done; (3) real data for Collector Default, Boulevard, Stroad (top rung shows Boulevard's Commonway configuration, linked) and RFT-CDR-01, done; (4) rollout to every pattern and Retrofit page and deletion of the five `Illustration*` components, done (130 pages; Local Default's illustration numbers became `loc-def-01.ts` instead of being dropped, because its reference 2 was cited nowhere else); (5) docs, done: How to Read a Pattern's "The Pattern viewer" section (replaced Illustrations; `#the-pattern-viewer` is linked from How to read a retrofit strategy's new "Before and after" section and the Brand Guide), the Brand Guide's "Pattern viewer" component entry (plus two accessibility-table rows: badge 8.97:1; amber outline 1.97:1 on light paper, documented as never the only signal), and the Accessibility Policy's "Pattern viewer" section; (6) accessibility pass, done: 520 axe scans (all 130 viewer pages, four modes), 96 on drawn states, Display settings modes, full view, keyboard walk, 320px reflow, emulated forced colors (found and fixed: drawing text and lines now use `CanvasText`/`Canvas` in forced colors, end of `viewer.css`). Later: a Streetmix JSON importer (`scripts/import-streetmix.mjs <file> <pattern-id> <rung>`) that fills only layer 1; Streetmix is AGPL, never copy its code or art.

- **Files:** types in `src/lib/viewer/types.ts` (read its header), state/URL/units helpers in `src/lib/viewer/state.ts`, components `PatternViewer` (parent, owns all state), `PatternViewerTabs`, `PatternViewerStage` (renderer registry), `PatternViewerControls`, `PatternViewerPending` (stand-in renderer). Data: one file per pattern, `src/lib/data/street-configs/<id-lowercased>.ts`, default-exporting `ViewerData`. Page usage, opening tag on one line: `<PatternViewer data={viewerData} image={fm.image} title={fm.title} classification="collector" />` (`retrofit` flag on Retrofit pages, `classification` = the scale's peer: corridor, intersections, network). With no `data` it shows `fm.image` as an Overview view (via the new 1280px copy, `PATTERN_VIEWER_WIDTHS` in `thumbs.ts`), or the tinted placeholder.
- **Data model, four layers, lengths always in feet:** segments (strips, Streetmix-like `type`/`width`/`variant`, with `items` inside so trees and lights share a strip), features along the street (`at` in feet: speed humps, PHBs, crosswalks), shape overrides (curb extensions change segment widths over a stretch), intersections (legs plus junction type). Items/features carry Element Pattern IDs (`elementId`). Segment ids must stay stable across a pattern's configurations: the change highlight matches by id.
- **Ladder, not toggles:** one configuration at a time, rungs `baseline` < `nacto` < `complete-streets` < `commonway` (a view lists only the rungs it has), `dutch` as a separate "for comparison" option, `before`/`after` on Retrofit pages. Lands on the top rung (or After). "What changed" is relative to the rung below. Annotations (labels, dimensions, highlight changes) are the only toggles. Facets (density tier, time of day) are optional selectors; an entry's `when` narrows it to facet values, the most specific match wins. Compare mode shows two configurations side by side (stacked when narrow), lower rung first.
- **Renderers:** every kind receives the same `RendererProps`. SVG renderers go in `renderers` in `PatternViewerStage.svelte` (imported normally, so they prerender); canvas/3D go in `lazyRenderers` (dynamic import, `poster` image until loaded, without JS and in print; libraries from npm, never a CDN). Kinds with no renderer show `PatternViewerPending`.
- **Deep links:** `?view=&config=&compare=&<facet id>=`, defaults omitted, written with `replaceState`. Facet ids must not be `view`, `config`, `compare`, `q`, `for`, `section`, `class` (dev warning). Units: `localStorage` key `commonway-viewer-units`.
- **Full view** is a modal `<dialog>`, body rendered in one place at a time. The viewer's own close paths call `closeDialog()` directly because the browser pane doesn't deliver dialog `close` events (the site search dialog shows the same; real browsers do). A `#` link inside full view closes it and then jumps (instant scroll; smooth scrolling doesn't run in the pane either).
- **Text-only/markdown:** `generate-text-pages.mjs` drops `.pv__bar`, `.pv__controls`, `.pv__live`, `.pv__away`, `.pvp` and `dialog`; the current description and "All configurations, in words" remain. The box is `data-pagefind-ignore="all"`; the all-configurations list is searchable.
- **Renderers (step 2; the drawing style, labels and glyphs described here were replaced on 2026.10.17, see "Pattern viewer art" below, but the Plan tab's polygons, markings, features, cut lines and the `geometry.ts` helpers still work as described):** `PatternViewerSection.svelte` (cross-section) and `PatternViewerPlan.svelte` (top down), palette in `src/lib/theme/styles/viewer.css` (site-only pavement/paint/planting colors with dark and high-contrast variants; amber `.hl`/`.badge` is the change highlight). Both measure their own box with a ResizeObserver and lay out in real pixels (a fixed viewBox made 12px labels 4px on a phone); SSR draws at 720x405 and re-lays out on mount. Everything is to scale: one feet-to-pixels scale, glyphs (people, cars, bus, cyclists, trees, lights, bollards, barriers...) drawn in feet inside `scale()` with `vector-effect: non-scaling-stroke`; the cross-section caps glyph scale so 19 ft trees and lights fit. Cross-section labels are rotated and fanned apart with `spread()` (geometry.ts), font shrinking to 9px before labels take more than a third of the height. The plan stacks strips top to bottom (cross-section left edge = top band), draws shape overrides as polygons through `breakpoints()`, markings by neighbor pair (double yellow between opposing lanes, dashed white same direction, solid yellow beside a turn lane, curb line between raised and road), arrows every 80 ft clear of the labels, items at their spacing, features at `at`, cut lines, and a scale bar; its length stretches to include every feature, override and cut. `geometry.ts` holds labels, `widthsAt()`, `diffStreets()` (numbered changes, identical texts share a number) and `spread()`; the parent computes the change list once and passes it to the renderer, so the badges and the "What changed from ..." list always match. Compare mode on a narrow viewer stacks two square panes (the stage drops its aspect ratio). Text-only/markdown drop `.pvx`. Not built: `intersection-plan` and `perspective` (they show `PatternViewerPending`), direction isn't drawn in the cross-section, and forced colors leaves the SVG fills as drawn (only text, lines and glyph outlines switch to system colors); checked in Chrome's emulation only.
- **Recipe: adding drawn views to a pattern that has none yet.** (1) Read the page's text, guidance table and References; collect every width the page or its sources actually state. (2) Write `src/lib/data/street-configs/<id-lowercased>.ts` (copy `art-blv-02.ts`'s shape): a header comment saying which widths are sourced (with the page's reference numbers) and which are only drawn as typical; one entry per researched rung (never invent a rung to fill the ladder; a single `commonway` entry is fine); stable segment ids shared across rungs; descriptions that stand on their own as the text alternative, citing the page's own reference numbers with `cite`. (3) If a source isn't in the page's References yet, add it (with its `EvidenceChip`) before citing it. (3b) Decide the drawn context, which isn't sourced and doesn't need a citation: `frontage` on every street configuration (`lawn`, `buildings`, `parking-lot`, `field`, per side; set it even when it's lawn, so the choice is visible), `surface` only where a strip differs from its type's default (bike lanes are green unless set to `asphalt`), `marking: 'sharrow'` on travel lanes bicycles share, and `people` only where who's on the sidewalk is the point (children for a School Street). (4) On the page, add the import and `data={viewerData}` to the existing `<PatternViewer ... />` tag. (5) Check: `pnpm run check`, a look at both views in light and dark and at 375px, the "What changed" list reads sensibly rung to rung, then `qa.mjs` on the page with `?view=plan` and a `compare=` state too. Widths come from the page's sources, not memory; if a number can't be sourced, draw it as typical and say so in the file header.
- **Forced-colors testing:** Puppeteer's `emulateMediaFeatures` rejects `forced-colors`, but Chrome's DevTools protocol accepts it: `const cdp = await page.createCDPSession(); await cdp.send('Emulation.setEmulatedMedia', { features: [{ name: 'forced-colors', value: 'active' }, { name: 'prefers-color-scheme', value: 'light' }] })`. Test the mismatched case too (site `data-theme='dark'` with a light system palette), where text tied to site tokens disappears. A full 130-page `qa.mjs` run takes about 40 minutes and prints only at the end; run it in the background.
- **Documentation demos** use `<PatternViewer data={sampleViewer} title="Sample street" classification="..." demo />` with the fictional `src/lib/data/street-configs/_demo.ts` (same decoupling as the `ART-UMS-09` sample card). `demo` drops the viewer's own h2 (so it stays out of the page outline and can't duplicate `#pattern-viewer`) and turns off deep-link URL writing. Keep at most one non-demo viewer per page.
- **Every new pattern or Retrofit page gets the viewer** right after its summary paragraph (the ID card is the page header since 2026.10.18, see Page polish), opening tag on one line, followed by a blank line: `<PatternViewer image={fm.image} title={fm.title} classification="..." />` (add `data={viewerData}` and the import once a data file exists; add `retrofit` on Retrofit pages). Retrofit pages are headed "Before and after" only when their data has an `after` configuration, otherwise "Strategy viewer". When adding data for a page, check whether any reference is cited only inside the viewer's descriptions; that still counts as cited.
- **Data written in step 3 (each file's header lists what is sourced and what is only drawn as typical):** `art-blv-02.ts` (Multiway Boulevard only, the single Commonway configuration, at the 100 ft feasible minimum from Jacobs/Rofé/Macdonald's UCTC guidelines, Boulevard ref 2, and SF Better Streets, ref 3; both references added to the Boulevard page; exports `multiwayBoulevard` and `multiwayDescription` for reuse), `art-std-05.ts` (two rungs: "Stroad as built" as `baseline` with a label override, and "Commonway System: a Boulevard instead" importing `multiwayBoulevard`, linked to Boulevard; Stroad's two old Illustration blocks were removed), `rft-cdr-01.ts` (40 ft curb to curb before and after, from FHWA's Road Diet Informational Guide, added as the road diet's ref 4), `col-def-01.ts` (NACTO and Complete Streets now keep the 7 ft baseline parking lane, since NACTO's parking width was never sourced). Citation numbers in a data file are the page's own References, so a configuration reused on another page (Stroad's Boulevard) carries no `cite` there. Research notes: NACTO's site is behind a Cloudflare bot check the Browser pane can't pass (don't try to get past it); FHWA's rdig.pdf downloads rather than opening in the pane; text from a PDF can be pulled with a small Swift PDFKit script (`swift script.swift file.pdf`, `PDFDocument(url:).page(at:).string`), since `pdftotext` and Quartz Python aren't installed; escholarship.org item pages carry the full OCR text in the page.
- **Demo data is a first draft:** Collector Default's crosswalk at 200 ft (on every rung since 2026.10.20) and two cut points (Midblock, At the crosswalk) exist to exercise the renderers and are not sourced; its protected bike lane and furnishing widths are typical, not sourced.
- **Parking at crosswalks and curb extensions (2026.10.20):** `onCrosswalk(features, from, to)` in `geometry.ts`; no parked car (section, slice) and no stall T (slice, Plan tab) is ever drawn on a crosswalk, since parking there is illegal everywhere. **A curb extension is its own strip:** a zero-wide `furnishing` strip (`ce-l`/`ce-r`, label "Curb extension") sits beside each parking lane, and the curb-extension override grows it to the width of the parking lane plus the door buffer beside it while both go to 0 (the Plan tab's buffer hatch skips where a buffer narrows), so the extension is planting, not the parking lane's or a buffer's surface. Zero-wide strips are dropped by the section (as before), left out of `diffStreets` (the override's own line covers them), and the Plan tab now finds strip boundaries stretch by stretch between breakpoints among the strips actually there (a pair's consecutive stretches join into one path, so dashes run on). **A crosswalk paves every planting strip it crosses** as a walkway to the sidewalk: a `s-sidewalk` rect in the Plan tab, `p-concrete` in the slice, and in section a cut on a crosswalk draws the strip as a "Walkway" (sidewalk, no items) while the slice still gets the strip as it is. Collector Default: every rung has the crosswalk; the baseline runs parking to it (state code, ref 29); NACTO (ref 30) and Complete Streets get a curb extension over a typical length (186 to 214 ft, 6 ft taper); the Commonway rung stops parking 30 ft before each crosswalk edge (FHWA, ref 26; 171 to 229 ft plus a 6 ft taper). The Plan tab still draws no parked cars.
- **Crosswalk stripes, detectable warnings and stall marks (2026.10.20):** `crossing(f, shown)` in `geometry.ts` decides, from the strips actually there at the crosswalk, which strips get stripes (every strip that isn't walkable, `isWalkable()`: sidewalk, furnishing, curb, median; so bike lanes at any height get them, and walkways and medians don't) and where detectable warnings go. A crosswalk with `detectableWarnings: true` (a `StreetFeature` flag; US configurations, PROWAG R205/R305, Collector Default ref 31) gets a 2 ft (`WARNING_DEPTH`) yellow strip on each walkable strip at every edge where the crosswalk leaves it: `s-dw` rects in the Plan tab, domed rects in the slice (`--pvx-p-dw`, `--pvx-p-dw-dome`, light and dark), a thin cap on the surface in a section cut at the crosswalk. Stripes run on a 4 ft rhythm across the crossed span, clipped to each crossed strip. Stall Ts now go on the edge toward a travel lane (else the road-level side), skipping zero-wide strips, and get the brick joints only on a brick lane; Collector Default gives every rung's parking `marking: 'stalls'`. Only Collector Default sets `detectableWarnings` so far; the Boulevard's and the demo's crosswalks don't. **A continuous barrier stops at every crosswalk** (2026.10.21): `barrierRuns(features, from, to)` in `geometry.ts` splits the run, ending `BARRIER_GAP` (1 ft) short of each crosswalk edge, in the slice and Plan tab; a section cut on a crosswalk drops a buffer's barrier. **People crossing are drawn from the side** (2026.10.21): on a walkway in a section cut at a crosswalk (a strip the section converted, `c.s !== c.src`), `walkers()` picks from `CROSSING_POOL` (walker, walker-dress, cane, wheelchair; at most one wheelchair user among crossers per drawing) with `CROSSING_WIDTH`, drawn by `pedestrianSide()` / `plainPedestrianSide()` heading toward the road's middle. Sidewalk people stay front views. The slice doesn't show the crossers (its spot finder keeps people off crosswalks).

## Pattern viewer choices within a layer (2026.10.19)

Facets now drive real choices; first used on Collector Default (`col-def-01.ts`: `parking` none/left/right/both on every rung but Dutch, `bikes` street/sidewalk on the Commonway rung only). Rules:
- **A facet applies to a configuration when one of its entries names it in `when`** (`facetApplies()` in `state.ts`); elsewhere its buttons are disabled with "Doesn't apply to ...". No separate flag.
- **Generate the combinations in the data file** with small `side()`/`street()`/`describe()` helpers, never by hand; keep segment ids identical in every combination (the diff and "moved" match by id). `when` must be typed `Record<string, string>` or svelte-check rejects the union.
- Facets render as button rows (`.pvc__choices`), not dropdowns. Compare can target `facet:option` (`CompareTarget`, also `?compare=parking:both` in the URL): pane two is the same rung with that choice, and its "What changed" counts from pane one. Panes carry a `key` (two panes can share an entry id).
- `diffStreets` now reports **moved** strips (heaviest common subsequence by `STAY_WEIGHT`, so travel modes are the ones reported) with their new neighbors, nearer-property-line first so both sides share one number, and a **right-of-way** change line. Level changes are reported too.
- **`Segment.level`** (`road | intermediate | sidewalk`, default from `levelOf()` in `geometry.ts`; `isRaised` and the art's `isRaisedSegment` both derive from it). `intermediate` sits at 0.4 of the curb; where it meets a sidewalk, `edgeStripLow()` draws a sloped edge strip (section, slice) instead of a curb. `Segment.shortLabel` names a strip too narrow for its `label`.
- Descriptions end with the right of way ("Right of way: 60 ft."), since widths now change with the choices.
- **The ladder switches to `CONFIG_COMPACT_LABELS`** (Base, Complete...) when its short labels overflow, measured in `PatternViewerControls` (run the check with `untrack`, or it loops: `effect_update_depth_exceeded`). Its tooltip is clamped to the ladder's width and flips below it inside a scrolling panel (full view).
- **Ladder layout (2026.10.21):** the ladder fills its column (`width: 100%`); rungs and references are two boxes (`.pvc__rungs`, `--refs`) 3px apart, each with its own 1px border, flex-grow by button count; the ends facing the gap are square. Chevrons overlap by `--pvc-d` less 1px (`.pvc__seg + .pvc__seg--notch`; a plain `.pvc__seg--notch` selector loses to `.pvc__seg + .pvc__seg` and widens every divider to the chevron depth). Fitting is measured in steps (`steps`/`fit`/`reached()`: short labels, compact labels, `tight` (13px text, less padding), `wrap` (the references box on its own full-width line; only with references), `split` (rungs at `flex: 1 1 34%` with `min-width: max-content`, so two to a line, square at each line's ends via `breakAt`; only with 3+ rungs); each step keeps the ones before it), by summing each face's `scrollWidth - clientWidth` (faces have `min-width: 0; overflow: hidden` so that's visible). `needed` is stored in rem, so switching Text size steps back down correctly; after any step it re-checks on the next frame, since the column's size didn't change. No 480px media query any more. The Browser pane, when hidden, runs as a background page and delivers neither `requestAnimationFrame` nor ResizeObserver callbacks, so the steps look stuck there; test with headless puppeteer instead. Nothing clips at any Text size on a 375px phone (Collector Default, five buttons). Zero-basis flex items never wrap, which is why `split` uses a 34% basis rather than `flex: 1 1 0` plus a break element.
- **Brick, raised parking and stall marks (2026.10.19, Collector Default's Commonway rung).** Surfaces `brick` (tan, only an illustration) and `brick-red` (not used yet); joints come from `brickJoints()` in `art/core.ts`, a joints-only pattern laid over any fill (brick color, or white for a T mark). `edgeStrip()` in `art/scene.ts` (was `edgeStripLow`) returns which side is low and which strip the slope sits in: a raised bike lane's slope sits in the bike lane, a raised (`intermediate`) parking lane's mountable curb sits in the parking lane so the travel lane keeps its width, and the section shortens that strip's slab by the slope. Parking with `marking: 'stalls'` gets a white brick T every `STALL_LENGTH` (22 ft, `geometry.ts`) on the edge nearest the travel lane, in the slice and Plan tab; a car in such a lane sits in the stall nearest the cut. Raised parking is outside curb to curb automatically (`isRaised`). A brick buffer keeps its white chevrons (slice) and hatch (Plan tab), the same as an asphalt one. Every buffer, asphalt or brick, barrier or not, gets a white stripe just inside each edge in all three drawings (the lane's own edge line is skipped there so it isn't doubled). Sources: Collector Default refs 20-22. Haarlem's own Harmenjansweg design document (gemeentebestuur.haarlem.nl) sits behind a bot check, so it isn't cited; per a search summary it puts the parking at full sidewalk height in red herringbone brick with white corner marks.
- **Puppeteer element screenshots** of the controls once painted the first button row as a blank gray box; a full-page screenshot showed it fine. Don't chase that.

## Pattern viewer art (2026.10.17, Phases 1-6 of the cross-section redesign)

The cross-section and both top-down views are drawn in an illustrated style approved from a mockup (`mockups/pattern-viewer-section-v2.html`, untracked, excluded in `.git/info/exclude`). Code: `src/lib/viewer/art/` (pure functions returning SVG strings: `core.ts` conventions and seeded random, `text.ts` Inter width table, `nature.ts`, `people.ts`, `vehicles.ts`, `items.ts`, `plain.ts`, `scene.ts` for the section's sky/ground/frontage, `slice.ts` for the aligned top-down slice), `src/lib/viewer/section-layout.ts` (dimension rows and zone band), and the palette at the top of `viewer.css` (`--pvx-*`, with dark and high-contrast values).
- **The markup must be identical at build time and in the browser.** No `Math.random`, clock or DOM in art functions; every seed comes from `seedOf(segment id, ...)`, so the same strip looks the same on every rung and every load. Label widths come from the Inter table in `text.ts` on the first render, and from the browser's own font (reading font, Simplified view) after mount. Clip-path and stamp ids are prefixed with the renderer's `$props.id()` because Compare and full view put two drawings on a page.
- **Art goes in with `{@html}` inside a transformed `<g>`** (`place(x, y, scale, art)`); this works in SVG at build time (tested). Front views have the origin at the ground, y up negative; top views run along y with +y toward the reader; the Plan tab turns them 90 degrees.
- **Simplified view** hides `.art` and the clouds and shows `.art-plain` (the old outline symbols, `plain.ts`), drawn from the same placements; the slice and Plan items (`.art--slice`) stay, being plan diagrams already. A new drawn object needs both an illustrated and a plain version.
- **Height:** in normal view the cross-section sets its own height from its width (`layoutAt(width, null)`); before mount it's a `calc(Kcqw + Cpx)` fitted at 360 and 720 px so the page doesn't jump; full view fits the box. The stage's `pv__stage--natural` class turns off the 16:9 aspect for this view.
- **Repeated items** (trees at a spacing in the slice and Plan tab) are drawn once with `makeStamps()` and reused with `<use>`.
- **Weight:** about 90 KB raw, 11-13 KB compressed per drawing (Kevin agreed to measure the budget compressed). Check after adding art: `build/<page>/index.html`, the `.pvx` element.
- Data fields this added: `frontage` (StreetConfig), `surface`, `marking`, `people` (Segment); defaults are `surfaceOf()`/`markingOf()` in `geometry.ts`, and the "What changed" list reports surface and marking changes.
- **Lab mobile LCP rose to 3.8 s** on Collector Default with the bigger HTML (largest paint is the h1; earlier lab runs were 2.7-3.3 s). Re-measure live after deploy.
- **Phase 7 (docs and accessibility) is done:** How to Read a Pattern ("Reading the cross-section"), the Brand Guide's Pattern viewer entry (which records that the viewer's illustrated style deliberately departs from the Illustration & photography rules for hand-drawn art: full-color people, more than three per drawing, no grayscale context; those rules still govern hand-drawn illustrations) plus four zone-band contrast rows, and the Accessibility Policy's Pattern viewer section. 572 axe scans (132 viewer pages plus 11 drawn states, four modes) were clean. Known limitations: drawing labels are px and don't follow the Text size setting; forced colors keeps the drawings' fills (including the dark fade under the ground cut).
- **Zone band rules** (`section-layout.ts`): a strip's zone comes from its type, except a planting strip, which is pedestrian only when it borders a sidewalk or curb and a hatched separator otherwise (the Dutch layout). Separators are hatched in their neighbors' colors, with a neutral stripe when both sides are the same zone.
- **Adding a drawn object:** an illustrated front view and top view (people.ts / vehicles.ts / items.ts), a plain version in `plain.ts`, its width in the `*_WIDTH` table, and a look on a temporary demo page in both themes (see the test recipe below). Seed it from the strip id, never the position.
- **Test recipe that worked for build-vs-browser identity:** a temporary `src/routes/art-test/+page.svelte` that renders the markup and writes a hash of it into a `data-*` attribute; on mount it hashes again and compares (the attribute keeps the server's value). Check it under `pnpm run dev` and the built site, then delete the route (it would ship and show up in the site map as "Other pages"). Svelte's dev build also warns on `{@html}` mismatches, so a clean console in dev is a second check.
- **Mockup and screenshot tooling:** a standalone HTML mockup in `mockups/` opened in the Browser pane is a static snapshot (reload doesn't pick up edits; navigate again with `?v=N`). For reviews, small puppeteer-core scripts (borrowed with `createRequire` from pro-how-com, as `qa.mjs` does) screenshot `.pv__stage` per page, theme and width; Python's PIL is installed for tiling them into contact sheets. Set `localStorage` before load: `commonway-cookie-consent` = `'denied'` (a plain string, not JSON, or the banner covers the shot), `commonway-viewer-units` = `'m'`, and `commonway-display-settings` as JSON with `simplifiedView`, `textSize`, `contrast`, `readingFont`, `colorSymbols`, `enhancedFocus`. Puppeteer reports console warnings as type `'warn'` (filter on both `'warn'` and `'warning'`).
